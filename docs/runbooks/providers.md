# Provider configuration

Groq is used for hosted query resolution, reranking, generation and conversation summaries; offline judges remain planned. OpenAI is selected for embeddings only, using LangChain `OpenAIEmbeddings`, model `text-embedding-3-small`, and 768 dimensions. Set `EMBEDDING_PROVIDER=openai` and privately configure `OPENAI_API_KEY`. Existing Gemini generations remain supported with explicit `EMBEDDING_PROVIDER=gemini`; omitted selection preserves that earlier configuration. There is no automatic fallback between providers. Current environment names are in [.env.example](../../.env.example). Configure `RAG_GENERATION_ID`, `EMBEDDING_PROFILE_ID`, `QUERY_PROFILE_ID`, `RERANK_PROFILE_ID` and optional default `ANSWER_PROFILE_ID` with immutable operator-verified records.

For conversations beyond the 6000-token recent-history window, configure `SUMMARY_PROFILE_ID` with an independently verified Groq `summarization` profile and current project approval for its processors. Summaries use the same conservative budget, authorization, output scanning and uncertain-completion rules as other private calls. Missing configuration blocks long-context processing; it does not silently drop older context or select another role. Migration `0039_conversation_summaries` adds the private checkpoint; apply it through the normal backup/restore rehearsal before enabling this feature in development. Summaries build lazily on the next question, extend as history grows and rebuild after context/history/prompt invalidation. No summary profile is required for short conversations. Tests use mocked HTTP. Development now includes this migration through the separately verified 0040 cutover; live summary-profile eligibility and activation remain separate, with no paid summary calls performed.

Migration `0038_openai_embeddings` adds the OpenAI provider identity and admits only its embedding role. Switching providers requires a new immutable generation and newly embedded documents, even though both models use 768 dimensions. Never relabel existing vectors. Public catalog, private indexing and question embeddings use the same selected provider and generation checks. LLM requests continue to use Groq and its separate key.

LangChain uses the existing bounded HTTP transport after conservative admission, with retries and automatic text splitting disabled. One admitted request embeds one nonempty text of at most 8,192 UTF-8 bytes; framing counts toward the conservative profile input bound. The raw usage is retained for settlement, and model identity, single-input response index and unit-length vectors are validated. Dependency versions are locked and included in evaluation fingerprints.

The [official model price](https://developers.openai.com/api/docs/models/text-embedding-3-small) is US$0.02 per million input tokens, checked on 2026-11-02. Reverify before enabling a price card. Key/model metadata access establishes model visibility, not a successful paid embedding, billing reconciliation or private-processing consent. Read [OpenAI data controls](https://developers.openai.com/api/docs/guides/your-data) before approving a private processor; adding credits does not grant processing consent.

Profiles bind provider/model/backend/role/processor IDs, token/attempt bounds and price card. Enabled flags do not repoint identity. Verify actual account, capability, billing/prices and purpose eligibility before enabling. Do not send private content under a public/synthetic exception or billing-unknown/free configuration. Normal dispatch still checks owner/upstream access, source/assessment, consent and conservative global admission.

Local setup has disabled profiles for OpenAI embeddings, Groq GPT-OSS 20B query resolution/reranking and GPT-OSS 120B generation, with all environment profile IDs configured. Groq Inference APIs ZDR is enabled; OpenAI embedding abuse-monitoring retention defaults to up to 30 days. Effective private consent, generation and processor/profile enablement remain unapplied. Earlier SwapKr-only approval does not expand to other projects or to a new evaluation workload.
