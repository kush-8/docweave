# Retrieval and evidence

Retrieval stays hybrid: native full text/BM25 plus exact/HNSW vector search, RRF fusion and Groq reranking. Query resolution identifies required current dependencies; embed only after policy and provider admission. Personal worker defaults `RAG_LEXICAL_STRATEGY=bm25` and `RAG_VECTOR_STRATEGY=exact` are provisional. Configure immutable `RAG_GENERATION_ID`, embedding/query/rerank profiles and answer profile explicitly; do not infer a release winner from fixture results.

Eligible corpus is the project's private collections plus its selected, ready, currently permitted public revisions. BM25 corpus statistics and candidates use that same selected scope. Never fall back to another embedding generation or broader collection set. Check assessment, source/coverage/selection, processing consent, deletion and current owner/upstream access before indexing/retrieval and again before release. Operator public revocation fences all dependent selections; removing one private selection does not delete shared vectors.

Structured answers must reference supplied documentary evidence or supplied project context; advice is visibly inferred. Server constructs citation IDs/URLs from verified exact spans, locator/version and current authority. Old answers are not evidence; retained citations preserve snapshots but require current permission on every read. Credential checks are non-waivable.

Use `backend/tests/rag/test_retrieval.py`, `test_retrieval_fusion.py` and personal retrieval/answer-pipeline tests. The evaluation CLI is `python -m docweave.evaluation --help`; current operator CLI still accepts explicit actor/workspace/project/generation/collections, recorded query vectors and output paths. Its workspace argument is retained CLI scope compatibility, not a workspace product. Component reports are not full answer-quality evidence. See [tasks](../tasks.md) for full release evaluation and summaries.
