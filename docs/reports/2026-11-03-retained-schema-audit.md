## Bounded retirement candidates

### Invitations and obsolete product SQL entry points

No current Python repository/service/API caller of `Invitation` or the invitation functions was found. The model and registry still exist. Migration `0004_memberships` defines `list_members`, `change_member`, `create_invitation`, `list_invitations`, `revoke_invitation` and `accept_invitation`, grants their execution to `docweave_runtime`, and has `change_member` update invitations when an owner is demoted. The searched later migration sources contain no revocation of those named grants. This is source evidence; actual installed function definitions and grants still need inspection. Sources: [invitation model](../../backend/src/docweave/db/models/workspaces.py), [SQL declarations and grants](../../backend/alembic/versions/0004_memberships.py).

Potential smallest retirement: revoke the unused product entry-point grants in a forward migration while preserving retained records. A subsequent table removal would need to retire every function body that names `invitations`, remove `Invitation` from the model/registry, update the disposable fixture cleanup, and handle any preserved invitation rows explicitly. Keep `lock_workspace_owner` until all retained SQL callers have been traced. Sources: [function dependency on owner lock](../../backend/alembic/versions/0006_collection_policy.py), [disposable fixture cleanup, line 158](../../backend/tests/database/test_database.py).

Do not infer a reachable HTTP vulnerability from those grants: current HTTP routes and transaction scopes are separate controls. The confirmed finding is an obsolete retained SQL surface that can be narrowed after dependency and installed-grant verification.

## Cleanup, privacy and recovery findings

1. **Deleted chat text remains retained in the database.** `personal_delete_conversation` tombstones the conversation and cancels active turns/jobs. Later migrations clear summaries and private provider-response checkpoints. They do not erase `turns.message`, completed `turns.answer`, citation JSON or turn progress. No time-based turn purge was found in current runtime sources. Access removal is implemented; complete local content erasure is not established. Sources: [original deletion function, lines 86–94](../../backend/alembic/versions/0016_personal_conversations.py), [checkpoint cleanup](../../backend/alembic/versions/0033_recovery_release.py), [summary cleanup](../../backend/alembic/versions/0039_conversation_summaries.py), [turn model](../../backend/src/docweave/db/models/conversations.py).

2. **Document deletion removes payload/index data but retains metadata.** Its SQL tombstones document/source rows, clears the active version, fences ingestion leases and returns artifact IDs. A deletion trigger removes chunks and document indexes; the HTTP route removes returned files after commit. Immutable version/job metadata remains. An artifact-removal error after the DB commit needs the existing orphan reconciliation path. Sources: [document/source deletion SQL, lines 120–131 and 202–217](../../backend/alembic/versions/0008_ingestion.py), [chunk/index purge, lines 191–200](../../backend/alembic/versions/0009_retrieval.py), [HTTP deletion routes, lines 61–66 and 115–120](../../backend/src/docweave/api/routes/ingestion.py).

3. **Orphan artifact cleanup depends on the ingestion worker running.** The reconciler preserves referenced IDs, waits a default 300 seconds and deletes only old unreferenced UUID-named files. The ingestion worker invokes it on startup and every ten seconds. The personal worker has job/index/guardrail reconciliation but no artifact reconciler call. A deployment running only the personal worker would not perform that orphan sweep. Sources: [artifact reconciliation, lines 77–86](../../backend/src/docweave/services/ingestion.py), [ingestion startup/maintenance, lines 35–43](../../backend/src/docweave/workers/ingestion.py), [personal maintenance](../../backend/src/docweave/workers/personal.py).

4. **Auth expiry cleanup is opportunistic.** `begin_login` expires login-rate buckets, auth flows and sessions; session reads require an unexpired row and revoke invalid identities. No periodic auth retention task was found. Expired encrypted token rows can therefore remain until another login begins. Sources: [begin_login, lines 14–20](../../backend/src/docweave/services/github_auth.py), [auth expiry SQL, lines 14–30](../../backend/src/docweave/repositories/auth.py), [current-session checks](../../backend/src/docweave/services/github_auth.py).

5. **Backups preserve all data and need a separate retention/deletion rule.** Preservation inventories all `app`/`queue` tables and hashes complete original rows/artifacts. Baselines reject missing tables or columns; they cannot silently treat dropping a retained table as successful preservation. The current runbooks require keeping original backups/ledger and testing isolated restores. No automated backup expiry or post-restore deletion replay was found. A restoration from before a chat/document deletion could reintroduce its local content unless the operator handles those deletions before service resumes. Sources: [complete preservation inventory, lines 39–91](../../backend/src/docweave/repositories/ownership.py), [preservation comparison](../../backend/src/docweave/preservation.py), [restoration procedure](../runbooks/personal-projects.md), [database preservation rules](../runbooks/database.md).

6. **Readiness is deliberately unconditional 503.** The route currently raises HTTP 503 without evaluating dependencies or acceptance evidence. A future readiness change must use verified release gates rather than flip the constant after unit tests pass. Source: [health route](../../backend/src/docweave/api/routes/health.py).

These findings do not authorize deletion of retained financial evidence, private archives or old operations. They identify the minimum missing operational behaviors; no retention duration was invented.
