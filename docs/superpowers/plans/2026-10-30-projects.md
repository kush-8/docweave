# Backend project context implementation plan

> **For agentic workers:** Use superpowers:executing-plans, implementing in this session with one independent final review.

**Goal:** Persist manual project context with an owner-only default collection, durable pending documentation requests, tenant-safe reads and revision-checked owner edits.

**Architecture:** Reuse verified sessions, Actor, selected-tenant RLS, encrypted keyset cursors and the serialized workspace-owner SQL helper. Narrow fixed-search-path functions create/edit the project and its default collection/pending requests atomically; no general domain DML grants. Project-ID resolution discloses only the workspace of a currently accessible project.

**Tech stack:** Existing FastAPI/Pydantic, SQLAlchemy/asyncpg, Alembic and PostgreSQL; no new dependencies.

**Spec:** [architecture](../../architecture.md#public-contracts), [Task 1](../../tasks.md#task-1--reproducible-runtime-and-real-access-boundaries), [target API](../../../backend/openapi.yaml).

## Constraints and reach

- User requested `main`; work there. Backend only. Preserve existing data and unrelated files.
- Touch `projects.py`, `policy.py`, `main.py`, `models.py`, SQLSTATE mapping in `memberships.py`, revision `0005_projects`, database cleanup/seed fixtures, project tests, prior workspace/stub assertions and backend status/runbooks.
- Project creation requires exactly one nonempty manual stack or reviewed-stack ID. GitHub reviews are unimplemented: that path returns 501 without writing anything.
- There are no approved catalog/version selections, budget admission or workers yet. Manual dependencies receive stable server IDs and durable pending-review requests in the creation transaction. `source_state=pending_review`, `job_ids=[]`; no fabricated jobs, inferred versions, automatic latest selection or hosted/network calls. Approved-source job admission remains in the owning ingestion task.
- Default collection content is owner-only; current workspace members may read project context and its default collection ID. No collection/grant API is claimed.
- PATCH requires a positive integer expected revision and at least one changed field. Omission preserves fields; empty optional strings clear them. Replacing a manual stack supersedes pending requests and persists new ones atomically.

## Review focus

- Invalid/unknown/other-tenant IDs must share 404 without reflected context, including project child stubs.
- Membership/ownership loss while waiting for a workspace lock must deny writes.
- Concurrent edits with one expected revision permit one winner and one safe 409.
- Default collection/pending-request failure must roll back the project; no direct runtime writes/private request reads.
- Omitted/null/empty/NUL/extra input, forged dependency metadata and cross-scope cursors must fail safely.
