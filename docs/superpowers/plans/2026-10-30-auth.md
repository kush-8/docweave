# Authentication implementation and evidence

Implements the confirmed Keycloak design in `docs/architecture.md` and authentication contract in `backend/openapi.yaml`. The user authorized rebuilding after the reset and then explicitly restricted this implementation to the backend. Superpowers provides TDD and independent review; Ponytail limits this to the backend auth slice of Task 1.

Scope reaches backend configuration/routes/lifecycle, identity/session migration and grants, Compose/Keycloak/local SMTP, affected contracts/tests, and setup/status documentation. Frontend, workspace, invitation, project and AI implementations are outside scope.

Decisions: Keycloak owns email/password registration, verification, reset, and social brokers. Authlib owns OIDC code flow/token validation with S256 PKCE. PostgreSQL holds encrypted single-use login transactions bound to an HttpOnly browser cookie, hashed app session identifiers, encrypted provider tokens and shared login throttling. Sessions expire no later than their ID/access tokens; refresh and global IdP logout are outside this slice. Issuer/subject identifies a user; email never merges accounts or grants workspace membership.

The backend implements `/auth/login`, `/auth/callback`, `/me` and `/auth/logout`. No frontend routes or behavior change. Identity uses localhost:58080 and captured email localhost:8025. The callback is the configured application origin plus `/api/v1/auth/callback`, exactly allowlisted in Keycloak. Production requires HTTPS; explicit local HTTP only accepts loopback addresses.
