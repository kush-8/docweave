# Budget admission and provider profiles

> **For agentic workers:** Execute natively under superpowers:executing-plans, test first, with one independent read-only final review.

**Goal:** Bound financial admission before hosted work and expose configured profiles and own-tenant usage without making provider calls.

**Spec:** [Task 2](../../tasks.md#task-2--workspaceglobal-cost-admission-before-hosted-calls), [architecture](../../architecture.md#budget-models-and-telemetry), [API](../../../backend/openapi.yaml).

**Architecture:** Three new records: immutable versioned profiles, operator monthly workspace allowances, durable operation reservations. Serialize reserve/settle/cap changes using one PostgreSQL transaction advisory lock; sum ledger charges instead of maintaining fallible balance counters. Reserve conservative price-card/token/attempt maxima, round up to 12 decimal USD places, and pin the admission month using PostgreSQL Asia/Calcutta after lock waits. Unknown execution retains at least the maximum; definitive reconciliation is idempotent and immutable. Actual overruns are recorded, disable the underbounded profile and count against all future admission.

## Scope and reach

- User-selected `main`; backend only; baseline `ec0e578`. Preserve unrelated changes. No frontend, real provider calls, persistent development DB, commit/push/deployment.
- Add `budget.py`, `providers.py`, migration `0007_budget`, model records and tests; update main/stub registration, disposable cleanup, runtime/draft status and runbooks. Reuse Actor, tenant sessions, opaque cursors and immutable processor registry. No new dependencies.
- Public GET `/providers` returns configured profiles with safe disabled reasons. No production profiles/prices/capabilities are invented or enabled. Exact model/backend/processor IDs, token bounds, attempt bound and price card are immutable; eligibility/verification flags remain operator-controlled.
- Service `reserve_cost(actor, operation_key, profile_id, max_input_tokens, max_output_tokens, *, engine, project_id=None)` requires current membership, optional same-workspace project, bounded verified pricing/capabilities/account and enabled processors. Keys are content-free opaque intents, hashed at rest and unique per workspace across months. Replays return the original reservation, never a fresh dispatch permission.
- Service `settle_cost(reservation_id, actual_usd, execution_uncertain, *, actor, engine)` checks stored originator/workspace but can reconcile after membership revocation. No browser reservation/settlement/cap mutation endpoints. Future workers must additionally enforce current content/processor authority and a dispatch journal; financial reservation alone grants no inference permission.
- Workspace allowances are explicit per calendar month, 0–20 USD; missing allowance waits. All charges (reserved, uncertain retained, confirmed actual) count toward the shared 20 USD monthly ceiling. Caps are not global entitlements.
- Usage GETs expose workspace/project aggregates and own allowance only; global shortage has a generic status, with no global figures. One read snapshot avoids inconsistent totals/status. Decimal/numeric only, no floats.

## Review focus

- Concurrent workspaces and same-workspace requests must not overspend; cap/role changes after waits must be observed.
- Same operation with changed actor/payload must conflict without leaking the original; replay across months must not create a fresh call.
- Unknown/disabled/unpriced/unbounded profiles cannot reserve; immutability prevents silently changing cost/model/backend/processor meaning.
- Uncertain execution never releases capacity; definitive settlement/replay must not double charge or overwrite confirmed billing. Overruns must be recorded rather than hidden.
- Asia/Calcutta rollover, rounding, project attribution, cross-tenant usage/settlement and revocation must be exercised on restricted-role PostgreSQL.
